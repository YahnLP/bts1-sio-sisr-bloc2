# TP – VLAN et trunk entre deux commutateurs

*BTS SIO SISR 1re année – Bloc 2 – S06*

> [!NOTE]
> **But.** Situation : Comment séparer les services d'une entreprise (direction, commercial, informatique) sur les mêmes switchs ?
>
> **Comment ce TP fonctionne.** Avant de manipuler, tu écris ce que tu **anticipes** (« J'anticipe »). Puis tu testes et tu notes ce que tu **constates**. Tu **comprends** ce que fait chaque commande (« Je comprends »). Un **bilan de compétences** clôt la séance. Les parties de services (Linux, Windows Server) se font sur des **machines virtuelles réelles** ; le **simulateur réseau** sert aux manipulations d'équipements réseau.


> [!NOTE]
> **Matériel réel ou simulation.** Si le matériel est disponible, fais la section « Variante sur matériel réel » en fin de TP ; sinon travaille dans le **simulateur réseau** : le choix revient à l'enseignant. Cisco Packet Tracer reste possible en complément. Voir [Matériel réel ou simulation](../../ressources/materiel-reel.md).

## Objectif

Configurer 3 VLANs sur 2 switches, affecter des ports Access, et créer un trunk inter-switches permettant aux machines du même VLAN de communiquer d'un switch à l'autre.

## Étape 1 : Ouvrir la topologie (3 min)

1. Ouvre le simulateur, puis **Ouvrir** et choisis `TP-S06-vlan-trunk.json`.
2. Vérifie sur le schéma : 2 switches (SW-A, SW-B) reliés par Fa0/24, et 3 PC sur Fa0/1 à Fa0/3 de chaque switch.
3. Les PC sont déjà adressés :

| **PC** | **IP** | **Masque** | **Passerelle** |
|--------|--------|------------|----------------|
| PC-Dir-A | 192.168.10.11 | 255.255.255.0 | 192.168.10.1 |
| PC-Com-A | 192.168.20.11 | 255.255.255.0 | 192.168.20.1 |
| PC-Info-A | 192.168.30.11 | 255.255.255.0 | 192.168.30.1 |
| PC-Dir-B | 192.168.10.21 | 255.255.255.0 | 192.168.10.1 |
| PC-Com-B | 192.168.20.21 | 255.255.255.0 | 192.168.20.1 |
| PC-Info-B | 192.168.30.21 | 255.255.255.0 | 192.168.30.1 |

## Étape 2 : Test "Avant VLANs" (5 min)

Sur **PC-Dir-A** → Desktop → Command Prompt :
```
ping 192.168.20.11   (vers PC-Com-A, même switch)
ping 192.168.10.21   (vers PC-Dir-B, autre switch)
```

 **Résultats à noter :** Les pings fonctionnent-ils ? (Oui, pour les mêmes sous-réseaux si adresses cohérentes)

**Attention :** Attention : PC-Dir-A (192.168.10.11) ne peut pas pinger PC-Com-A (192.168.20.11) car IPs dans réseaux différents, **même sans VLAN**. Les VLANs ajoutent l'isolation L2, en plus de l'isolation L3.

**J'anticipe.** Avant de créer un VLAN, deux PC branchés sur le même switch (adresses du même réseau) se pingent-ils ? Pourquoi ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Oui : tous les ports d'un switch sont par défaut dans le **VLAN 1** : un seul domaine de diffusion, donc un seul réseau local.

</details>

## Étape 3 : Configurer SW-A — VLANs et Ports Access (15 min)

```cisco
! Accéder au switch SW-A
SW-A> enable
SW-A# configure terminal

! Renommer le switch
SW-A(config)# hostname SW-A

! Désactiver résolution DNS
SW-A(config)# no ip domain-lookup

! Créer les 3 VLANs
SW-A(config)# vlan 10
SW-A(config-vlan)# name DIRECTION
SW-A(config-vlan)# exit

SW-A(config)# vlan 20
SW-A(config-vlan)# name COMMERCIAL
SW-A(config-vlan)# exit

SW-A(config)# vlan 30
SW-A(config-vlan)# name INFORMATIQUE
SW-A(config-vlan)# exit

! Affecter Fa0/1 → VLAN 10
SW-A(config)# interface FastEthernet0/1
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 10
SW-A(config-if)# exit

! Affecter Fa0/2 → VLAN 20
SW-A(config)# interface FastEthernet0/2
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 20
SW-A(config-if)# exit

! Affecter Fa0/3 → VLAN 30
SW-A(config)# interface FastEthernet0/3
SW-A(config-if)# switchport mode access
SW-A(config-if)# switchport access vlan 30
SW-A(config-if)# exit

! Vérifier
SW-A(config)# end
SW-A# show vlan brief
```

**Validation :** Fa0/1 dans VLAN 10, Fa0/2 dans VLAN 20, Fa0/3 dans VLAN 30.

**J'anticipe.** Après avoir placé PC1 dans le VLAN 10 et PC2 dans le VLAN 20 (même switch, même réseau IP), se pingent-ils ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

**Non** : ce sont désormais deux domaines de diffusion séparés. Les trames d'un VLAN ne sont jamais transmises à l'autre : même branchés sur le même switch, ils sont isolés. Pour les faire communiquer, il faut un **routeur** (S09).

</details>


---

## Étape 4 : Configurer le Trunk sur SW-A (8 min)

```cisco
SW-A# configure terminal

SW-A(config)# interface FastEthernet0/24
SW-A(config-if)# switchport mode trunk
SW-A(config-if)# switchport trunk allowed vlan 10,20,30
SW-A(config-if)# exit

SW-A(config)# end
SW-A# show interfaces trunk
```

**Autorisé :** **Validation :** Fa0/24 en mode trunking, VLANs 10,20,30 autorisés.

**Je comprends.** Que se passerait-il pour les PC du VLAN 10 situés sur SW-A et SW-B si le lien entre les deux switchs était un port *access* du VLAN 10 ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Seul le **VLAN 10** passerait entre les deux switchs : les VLAN 20 et 30 seraient coupés. Un lien **trunk** transporte plusieurs VLAN, chaque trame portant une étiquette 802.1Q qui indique son VLAN.

</details>


---

## Étape 5 : Configurer SW-B (15 min)

**Même configuration sur SW-B** (VLANs identiques, ports identiques, trunk sur Fa0/24).

```cisco
SW-B> enable
SW-B# configure terminal
SW-B(config)# hostname SW-B
SW-B(config)# no ip domain-lookup

SW-B(config)# vlan 10
SW-B(config-vlan)# name DIRECTION
SW-B(config-vlan)# exit
SW-B(config)# vlan 20
SW-B(config-vlan)# name COMMERCIAL
SW-B(config-vlan)# exit
SW-B(config)# vlan 30
SW-B(config-vlan)# name INFORMATIQUE
SW-B(config-vlan)# exit

SW-B(config)# interface FastEthernet0/1
SW-B(config-if)# switchport mode access
SW-B(config-if)# switchport access vlan 10
SW-B(config-if)# exit

SW-B(config)# interface FastEthernet0/2
SW-B(config-if)# switchport mode access
SW-B(config-if)# switchport access vlan 20
SW-B(config-if)# exit

SW-B(config)# interface FastEthernet0/3
SW-B(config-if)# switchport mode access
SW-B(config-if)# switchport access vlan 30
SW-B(config-if)# exit

SW-B(config)# interface FastEthernet0/24
SW-B(config-if)# switchport mode trunk
SW-B(config-if)# switchport trunk allowed vlan 10,20,30
SW-B(config-if)# exit

SW-B(config)# end
SW-B# copy run start
```

## Variante sur matériel réel

**Matériel :** 2 commutateurs administrables, 6 PC (ou 4 PC et seulement les VLAN 10 et 20), 1 câble console, câbles Ethernet.

1. Remettre les deux commutateurs à zéro : `erase startup-config`, `delete flash:vlan.dat`, `reload`. Vérifier avec `show vtp status` qu'aucun domaine VTP ne reste configuré ; au besoin `vtp mode transparent`.
2. Relever les noms réels des ports (`show interfaces status`). Le lien entre commutateurs (`Fa0/24` dans le TP) peut être un port `Gi0/1` : adapter le schéma et les commandes.
3. Étape 1 : câbler les PC et le lien inter-commutateurs. Pour deux commutateurs de même type, utiliser un câble croisé si l'auto-MDIX n'est pas disponible.
4. Étape 2 (test avant VLAN) : régler les adresses IP dans le système des PC ; autoriser l'ICMP sur le pare-feu Windows pour que les ping soient possibles.
5. Étapes 3 à 5 : mêmes commandes. Sur certains modèles, `switchport trunk encapsulation dot1q` doit précéder `switchport mode trunk` ; si la commande est refusée, le modèle ne gère que le 802.1Q et `switchport mode trunk` suffit.
6. Étapes 7 et 8 : vérifier avec `show vlan brief`, `show interfaces trunk` et les voyants des ports.
7. Étape 6 et 9 : `copy running-config startup-config` sur chaque commutateur, puis enregistrer `show running-config` dans un fichier texte. Il remplace le fichier enregistré à l'étape 9.
8. Remise à zéro en fin de séance.
