# TP – Relier deux réseaux par un routeur

*BTS SIO SISR 1re année – Bloc 2 – S07*

> [!NOTE]
> **But.** Situation : Deux réseaux doivent se parler, et les postes doivent recevoir leur adresse automatiquement : que configurer, et où ?
>
> **Comment ce TP fonctionne.** Avant de manipuler, tu écris ce que tu **anticipes** (« J'anticipe »). Puis tu testes et tu notes ce que tu **constates**. Tu **comprends** ce que fait chaque commande (« Je comprends »). Un **bilan de compétences** clôt la séance. Les parties de services (Linux, Windows Server) se font sur des **machines virtuelles réelles** ; le **simulateur réseau** sert aux manipulations d'équipements réseau.


> [!NOTE]
> **Matériel réel ou simulation.** Si le matériel est disponible, fais la section « Variante sur matériel réel » en fin de TP ; sinon travaille dans le **simulateur réseau** : le choix revient à l'enseignant. Cisco Packet Tracer reste possible en complément. Voir [Matériel réel ou simulation](../../ressources/materiel-reel.md).

> [!TIP]
> **Ce TP se fait dans le simulateur réseau** (dans le navigateur, sans installation ni Internet).
>
> 1. Télécharge [TP-S07-routage-statique.json](tp/TP-S07-routage-statique.json){ download }.
> 2. Ouvre le [simulateur](../../simulateur/simulateur-reseau.html), clique sur **Ouvrir** et choisis ce fichier : équipements, câbles, adresses et sujet s'affichent.
> 3. Suis les étapes ci-dessous. **Vérifier mon travail** contrôle ta configuration ; **Charger la correction** montre une solution.
> 4. La liaison WAN utilise le port `gi0/1` des deux routeurs, car le simulateur n'a pas de port série.
>
> **Complément.** Cisco Packet Tracer reste possible : les commandes sont identiques, seules la création de la topologie et la sauvegarde changent (encadrés « Complément Packet Tracer »). Mode d'emploi : [Utiliser les TP du simulateur](../../ressources/simulateur.md).

## Objectif

Créer une topologie avec deux réseaux IP reliés par un routeur, configurer les interfaces et les routes statiques, et valider la connectivité inter-réseaux.

<details markdown="1">
<summary>Complément Packet Tracer : construire la topologie</summary>

2. Câbler avec le tableau de l'étape 2, mais la liaison WAN se fait en **série** : R1_INFO Se0/0/0 vers R2_DIR Se0/0/0 (Serial DCE d'un côté, DTE de l'autre ; `show controllers serial 0/0/0` indique le côté DCE). Les LAN utilisent Fa0/0 au lieu de gi0/0.
3. Régler l'IP, le masque et la passerelle de chaque PC (Desktop → IP Configuration) avec le tableau de l'étape 3.

## Étape 4 : Configurer R1_INFO (15 min)

Double-clique sur R1_INFO pour ouvrir le terminal. Les interfaces sont `gi0/0` (LAN) et `gi0/1` (WAN).

```cisco
Router> enable
Router# configure terminal
Router(config)# hostname R1_INFO
R1_INFO(config)# no ip domain-lookup

! Interface LAN côté Informatique
R1_INFO(config)# interface GigabitEthernet0/0
R1_INFO(config-if)# description LAN Informatique 192.168.10.0/24
R1_INFO(config-if)# ip address 192.168.10.1 255.255.255.0
R1_INFO(config-if)# no shutdown
R1_INFO(config-if)# exit

! Interface WAN vers R2
R1_INFO(config)# interface GigabitEthernet0/1
R1_INFO(config-if)# description WAN vers R2_DIR
R1_INFO(config-if)# ip address 10.0.0.1 255.255.255.252
R1_INFO(config-if)# no shutdown
R1_INFO(config-if)# exit

! Route statique vers le réseau Direction
R1_INFO(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2

R1_INFO(config)# end
R1_INFO# copy running-config startup-config
```

> [!NOTE]
> **Sur Packet Tracer ou sur matériel :** le LAN est sur `FastEthernet0/0` et le WAN sur `Serial0/0/0`. Côté DCE, ajouter `clock rate 64000` sur l'interface série.

**Vérification :**
```cisco
R1_INFO# show ip interface brief
R1_INFO# show ip route
```

**Attendu :** Gi0/0 et Gi0/1 en **up/up**, route S vers 192.168.20.0/24 présente.

**J'anticipe.** Une fois les deux interfaces de R1 configurées, quelles routes `show ip route` affiche-t-il ? Connaît-il le réseau situé derrière R2 ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Il n'affiche que les routes **connectées** (code **C**) : les réseaux directement branchés sur ses interfaces. Le réseau derrière R2 est **inconnu** tant qu'on n'a pas ajouté de route statique (code **S**).

</details>

## Étape 5 : Configurer R2_DIR (10 min)

```cisco
Router> enable
Router# configure terminal
Router(config)# hostname R2_DIR
R2_DIR(config)# no ip domain-lookup

R2_DIR(config)# interface GigabitEthernet0/0
R2_DIR(config-if)# description LAN Direction 192.168.20.0/24
R2_DIR(config-if)# ip address 192.168.20.1 255.255.255.0
R2_DIR(config-if)# no shutdown
R2_DIR(config-if)# exit

R2_DIR(config)# interface GigabitEthernet0/1
R2_DIR(config-if)# description WAN vers R1_INFO
R2_DIR(config-if)# ip address 10.0.0.2 255.255.255.252
R2_DIR(config-if)# no shutdown
R2_DIR(config-if)# exit

! Route statique vers le réseau Informatique
R2_DIR(config)# ip route 192.168.10.0 255.255.255.0 10.0.0.1

R2_DIR(config)# end
R2_DIR# copy running-config startup-config
```

## Étape 6 : Tests de Connectivité (10 min)

Depuis **PC-INFO-01** → Desktop → **Command Prompt** :

```
Test 1 : Ping local (même réseau)
> ping 192.168.10.12
Attendu : 4 réponses correctes

Test 2 : Ping passerelle
> ping 192.168.10.1
Attendu : 4 réponses correctes

Test 3 : Ping inter-réseaux (LE TEST CLÉ)
> ping 192.168.20.11
Attendu : 4 réponses correctes
(1er ping souvent KO = ARP, les 3 suivants OK)

Test 4 : Ping autre PC côté Direction
> ping 192.168.20.12
Attendu : 4 réponses correctes
```

Depuis **R1_INFO** :
```cisco
R1_INFO# ping 192.168.20.1     ! Ping routeur distant
R1_INFO# ping 192.168.20.11    ! Ping PC côté Direction
R1_INFO# show ip route          ! Vérifier toutes les routes
R1_INFO# traceroute 192.168.20.11   ! Voir le chemin
```

**Je comprends.** PC1 envoie un ping à PC2 et reçoit « délai dépassé », alors que R1 a une route vers le réseau de PC2. Où chercher ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Un ping demande un **aller-retour** : R2 doit aussi connaître la route **de retour** vers le réseau de PC1 (et PC2 doit avoir une passerelle correcte). Un routage statique se configure **dans les deux sens**.

</details>

## Variante sur matériel réel

**Matériel :** 2 routeurs, 2 commutateurs, 4 PC, 1 câble console, câbles Ethernet ; un module série et un câble série DCE/DTE si l'on garde la liaison WAN en série.

1. Remettre routeurs et commutateurs à zéro, puis relever les noms réels des interfaces (`show ip interface brief`). Adapter le plan d'adressage : `Fa0/0` peut être `Gi0/0`.
2. **Liaison WAN.** Sans module série, remplacer le lien série par un lien **Ethernet** entre les deux routeurs (par exemple `Gi0/1` à `Gi0/1`), avec les mêmes adresses `10.0.0.1/30` et `10.0.0.2/30` ; il n'y a alors pas de `clock rate`. Avec un module série, repérer le côté DCE par `show controllers serial 0/0/0` et configurer `clock rate` de ce côté seulement.
3. Les interfaces d'un routeur sont **désactivées par défaut** : `no shutdown` sur chacune.
4. Les routes statiques, les tests et la grille de validation sont identiques. Autoriser l'ICMP sur le pare-feu des PC Windows.
5. Étape 7 : `copy running-config startup-config`, puis enregistrer `show running-config` de chaque routeur dans un fichier texte.
6. Remise à zéro en fin de séance.
