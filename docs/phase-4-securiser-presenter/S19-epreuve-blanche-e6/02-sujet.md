# Sujet – Épreuve blanche E6

*BTS SIO SISR 1re année – Bloc 2 – S19*

> [!NOTE]
> **Sujet d'entraînement, non officiel.** Il reproduit les **conditions** de l'épreuve E6 (1 h 30 de préparation, 40 minutes d'oral) à partir de **ta propre réalisation**. L'épreuve nationale se fait sur **deux réalisations** présentées chacune par une fiche descriptive ; ici, tu en présentes **une**, en 1re année. Les textes officiels (arrêté du 8 juillet 2024, circulaire en vigueur) font foi.

## Conditions

| Élément | Détail |
|---|---|
| **Préparation** | 1 h 30, seul, avec ton dossier (DAT, fiche descriptive, captures, fichiers de configuration) et un poste de démonstration |
| **Oral** | 40 minutes devant un jury (enseignants ou pairs) |
| **Support** | Une réalisation du bloc 2 : projet de PME (S17-S18) ou toute autre réalisation (S06 à S16) |
| **Interdit** | Présenter une réalisation **uniquement simulée** : une machine virtuelle ou une situation d'entreprise doit la soutenir |

## Consignes pour la préparation

À partir de ta réalisation, prépare **en 1 h 30** :

1. **Une présentation structurée** (5 à 8 vues ou un plan écrit) : contexte, besoin, architecture et schéma, choix techniques justifiés, sécurité, tests, exploitation, limites et améliorations ;
2. **Un schéma réseau** lisible (adressage, VLAN, services, zones de sécurité) ;
3. **Une démonstration** de 5 minutes, répétée une fois (une manipulation qui prouve que ça marche) ;
4. **La liste des questions** que le jury pourrait te poser et ta réponse à chacune (au moins six).

## Consignes pour l'oral

- **15 minutes** de présentation, **sans lire** : le schéma est ton appui.
- **Démonstration** d'environ 5 minutes.
- **20 minutes** d'échange avec le jury.

## Grille d'observation (outil de formation)

Cette grille n'est **pas** la grille nationale : elle sert à donner un retour structuré. Niveaux : non maîtrisé, maîtrise partielle, bonne maîtrise, excellente maîtrise.

| Critère | Ce qu'on observe | Niveau | Remarque |
|---|---|---|---|
| **Réalité de la réalisation** | Environnement réel (VM ou entreprise), pas une simulation ; preuves datées | | |
| **Conception** | Besoin compris, plan d'adressage cohérent, choix justifiés (pourquoi pas autre chose ?) | | |
| **Mise en œuvre** | Configuration correcte et expliquée, tests menés, démonstration fonctionnelle | | |
| **Exploitation et sécurité** | Moindre privilège, filtrage, sauvegarde, supervision, documentation | | |
| **Qualité de la démarche** | Méthode de diagnostic, gestion des erreurs, limites reconnues | | |
| **Communication** | Plan clair, vocabulaire précis, schéma lisible, tenue du temps | | |

### Questions types du jury

- Pourquoi ce plan d'adressage ? Que se passe-t-il si l'entreprise double son nombre de postes ?
- Comment as-tu **prouvé** que le service fonctionne ? Montre-le.
- Que se passe-t-il si le serveur DHCP (ou DNS, ou le contrôleur de domaine) tombe ?
- Quels sont les flux autorisés entre les zones ? Pourquoi ceux-là ?
- Comment les utilisateurs sont-ils protégés des erreurs de manipulation ? et d'un compte compromis ?
- Quelle est ta **part** dans la réalisation si elle a été faite en équipe ?
- Qu'améliorerais-tu avec une semaine de plus ?
